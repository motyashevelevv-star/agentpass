# Архитектура AgentPass

AgentPass решает вопрос «уполномочен ли этот агент совершить конкретное действие?». Он не ведёт банковский баланс и не является платёжным провайдером. Reservation — логический резерв бюджета мандата, а не блокировка денег на счёте.

## Компоненты

| Компонент | Ответственность |
|---|---|
| Next.js App Router | User Dashboard, Developer Portal, Agent Console, Admin Console; same-origin proxy к API |
| FastAPI | Валидация, сессии, RBAC, REST v1 и бизнес-транзакции |
| PostgreSQL 16 | Источник истины: полномочия, версии правил, решения, резервы, подтверждения и аудит |
| Outbox worker | HTTP-доставка webhook, повторные попытки, освобождение истёкших резервов и подтверждений |
| TypeScript SDK | API-ключ агента, намерения, polling, отмена и симулированное исполнение |
| Каталог/интерпретатор | Детерминированное сопоставление товара и бюджета; финансовых решений не принимает |

Redis не используется: PostgreSQL обеспечивает блокировки, очередь и атомарный rate limiting. Это уменьшает число источников истины.

## Обработка намерения

1. Проверка сессии или хеша Bearer-ключа; организация должна быть активна. Ключ привязан к агенту и сроку.
2. PostgreSQL advisory lock по организации, агенту и idempotency key. Повтор идентичного body возвращает исходное намерение; изменённое тело даёт 409.
3. Проверка owner/org/agent. Затем блокировки в порядке agent → mandate → intent → approval/reservation. Все писатели бюджета используют тот же порядок.
4. Освобождение истёкших резервов мандата. Проверка статуса агента, мандата, периода, валюты, категории, продавца, лимита операции и суммарных бюджетов.
5. DENY сохраняет объяснение без резерва. ASK создаёт одноразовое подтверждение на 15 минут без резерва. APPROVE создаёт резерв на 15 минут.
6. Решение, резерв/подтверждение, audit и webhook outbox фиксируются одной транзакцией. До commit результат не считается долговечным. FastAPI DB dependency имеет scope="function": commit завершается до отправки HTTP-ответа. Сбой commit возвращает ошибку и откатывает бизнес-записи.

Значения денег — положительные целые минимальные единицы валюты. Нет float-арифметики в engine. MVP создаёт рублёвые мандаты; иная валюта намерения даёт DENY. Все deny-правила проверяются до порога ASK. Запрет продавца имеет приоритет над allowlist.

## Подтверждение и исполнение

Пользовательское согласие привязано к одному intent, владельцу и сроку. Backend повторно блокирует агент и мандат, проверяет актуальные правила и заново вычисляет бюджеты. Только затем создаёт резерв. Конкурентное повторное подтверждение получает 409; уникальный `approval.intent_id` предотвращает второй запрос согласия для того же intent.

`POST /intents/{id}/execute` отдельный от решения. Он проверяет активность мандата/агента, срок резерва, текущие бюджеты и версию правил. Изменённая версия перед исполнением инвалидирует разрешение и освобождает резерв; требуется новый intent. Исполнение создаёт единственный simulated transaction и переводит резерв в consumed. Повтор возвращает прежний чек.

На границе суток/недели/месяца исполнение повторно проверяет текущий UTC-бюджет, исключая собственный резерв, и переносит его учётную дату на момент исполнения. ASK после изменения правил проверяет актуальную версию; согласие разрешает преодолеть только порог подтверждения, не deny-правила.

## Границы бюджетов

День — 00:00 UTC; неделя — понедельник 00:00 UTC; месяц — первое число 00:00 UTC. Расход учитывает held и consumed резервы, а также inflight во всех текущих временных окнах до сверки. Отмена/истечение освобождает held; завершённую покупку отменить нельзя. Бюджет независим для каждого мандата: это не общий лимит банковского счёта и не общий бюджет агента.

## Доставка событий

Outbox хранится в том же PostgreSQL commit, что и бизнес-действие. Worker выбирает одну доставку через `FOR UPDATE SKIP LOCKED`, подписывает точные UTF-8 bytes и отправляет HTTP. До пяти попыток: интервалы после ошибок 15, 30, 60, 120 секунд. Доставка at-least-once; потребитель обязан дедуплицировать `X-AgentPass-Delivery`.

Публичные endpoints: HTTPS:443, разрешение DNS при каждой попытке, отказ от приватных IP, соединение с проверенным IP при сохранении TLS hostname. Redirects не исполняются. В sandbox допускается только один заранее заданный HTTP URL локального receiver; он проверяет HMAC, время и delivery/event IDs, сохраняет дедуплицированный receipt. Это реальная доставка по HTTP, без внешнего сервиса.

## Эксплуатационные ограничения

Worker держит блокировку доставки во время ограниченного сетевого вызова (timeout 5 секунд). Это компромисс MVP; нагрузочный пилот должен заменить его lease-механизмом. Очистка сроков выполняется примерно раз в минуту и при обращении к мандату. Истёкшее согласие или резерв никогда не исполняются, даже если worker остановлен.

Сессии и API-ключи централизованы в БД. Отзыв ключа сериализуется с его запросами; статус организации защищён shared lock на время авторизованной транзакции. Сессия, проверенная до её отзыва, может завершить уже начатый запрос.

Аналитика рассчитана из записей БД; рублёвые расходы отображаются отдельно от намерений. Нет чисел из frontend mock arrays. Исторический seed содержит одну архивную симулированную покупку; это явно обозначенный fixture. Настоящих платежей и адаптера банка нет.

Удаление участника блокируется с его запросами через membership row lock и отзывает его API-ключи. Ключ дополнительно проверяет актуальное членство и роль создателя при каждом запросе; viewer или удалённый участник не сохраняет агентский доступ. Порядок auth locks: организация → членство → ключ.

## Исполнение через grant и payment outbox

Новый путь: intent → grant (120 секунд) → POST executions → committed queue → worker lease → provider → validated evidence → receipt. Исполнение не проходит внутри HTTP-транзакции. Claim блокирует финансовые сущности в общем порядке, перепроверяет правила и переводит held в inflight, затем фиксирует lease на 30 секунд. Во время provider I/O финансовые блокировки не удерживаются. Lease token ограждает поздний ответ от перезаписи новой попыткой.

Timeout/crash даёт unknown; нет успешной transaction и нет освобождения бюджета. Локальный провайдер имеет отдельный долговечный журнал и вечный idempotency key; retry сначала делает reconcile. ЮKassa без известного payment ID не пересоздаёт неоднозначный checkout, а требует callback/refetch или operator reconciliation. Callback — недоверенная подсказка; состояние читается через аутентифицированный API провайдера и сверяется с frozen hash/amount/currency/test shop.

10 неудачных/нефинальных попыток — логический quarantine; ручной reconcile или проверенный callback запускает новую серию. Успех пишет transaction и consumed только по подтверждённому test result. Истечение/отзыв после отправки не освобождают inflight; это не отмена у провайдера. Public refund/cancel provider workflow пока отсутствует. Legacy execute сохранён только для sandbox/development и использует тот же local provider в одной DB-транзакции.
