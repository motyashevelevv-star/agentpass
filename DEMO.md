# Демонстрация для Академии Финтеха

## Подготовка

Для полного доступа ко всем четырём интерфейсам выполните `npm run sandbox`, откройте http://localhost:3000 и нажмите **«Открыть полный sandbox»**. Используется обычная серверная авторизация sandbox-администратора. При первом входе под этим аккаунтом создаются агент и мандат, если агентов ещё нет. Все дальнейшие операции выполняются через общий API и Policy Engine.

Запустите Compose по README и войдите как `demo@agentpass.local` с локальным паролем `AgentPass-demo-2026!` (либо вашим `DEMO_PASSWORD`). Начальные данные содержат настоящие записи в БД: архивную симулированную покупку и запросы ASK/DENY. При первоначальном seed историческая дата одной операции перенесена на вчера для иллюстрации аналитики; текущий бюджет не расходуется этим fixture.

В Agent Console нажмите **«Новый демо-бюджет»**. Backend создаст нового Personal Shopping Assistant и новый мандат, UI автоматически выберет его. Это повторяемый сценарий без ручного редактирования или очистки БД. Старые действия остаются в аудите.

Правила нового мандата: одна операция 15 000 ₽; день 25 000 ₽; неделя 100 000 ₽; месяц 250 000 ₽; электроника; согласие от 10 000 ₽ включительно; срок 30 дней.

## Три решения

1. **APPROVE:** «Купи наушники до 8 000 рублей». Интерпретатор выбирает Soundcore Life Q30 за 8 000 ₽. Общий API создаёт Payment Intent, engine проверяет правила и резервирует бюджет, console вызывает отдельный execute. Покажите чек симуляции и использованные 8 000 ₽.
2. **ASK:** «Купи наушники до 12 000 рублей». Выбран Sony WH-CH720N за 12 000 ₽. Создаётся одноразовое подтверждение на 15 минут без резерва. Откройте «Подтверждения» в новой вкладке, подтвердите запрос. Engine заново проверит правила, создаст резерв, а открытая console получит результат через polling и выполнит симуляцию. Использовано 20 000 ₽.
3. **DENY:** «Купи наушники до 18 000 рублей». Выбран Marshall Major V за 18 000 ₽. Превышен лимит одной операции; возможна также причина превышения оставшегося дневного бюджета. Никакой покупки или резерва. Покажите объяснение, намерение в истории и запись аудита.

Это один backend и один engine, без трёх заранее заданных verdicts. Измените лимит или категорию мандата и повторите запрос: решение изменится в соответствии с правилами.

## Дополнительные проверки

- В Playground выберите мандат и измените merchant/category/currency. «Проверка правил» не создаёт intent; «Создать Intent» использует настоящий budget reservation. Повтор идентичного JSON показывает тот же ID; изменённый body с прежним ключом даёт 409.
- Создайте ASK, затем уменьшите лимит мандата. Подтверждение уже ожидающего запроса повторно проверит новую версию и может вернуть DENY.
- Создайте APPROVE в Playground, отмените его в деталях операции. Использованный бюджет уменьшится. Отзыв мандата инвалидирует ожидающие/неисполненные операции и освобождает резервы.
- В Developer Portal → Webhooks добавьте endpoint, нажмите «Использовать локальный receiver», сохраните выданный секрет и отправьте «Тест». Покажите delivered, HTTP 200 и receipt с проверенной подписью. Worker должен работать.
- Запустите `infra/smoke.py`: SDK создаёт/повторяет/исполняет/отменяет реальные sandbox intents, пользователь подтверждает ASK через API, затем проверяется настоящая HTTP-доставка webhook.
- Войдите как `admin@agentpass.local`, откройте Admin Console. Есть организации, API status/latency, события и новый sandbox-набор. Обычный пользователь не имеет административного доступа.

## Объяснение границ

AgentPass проверяет полномочия, а не платёжеспособность. «Бюджет» — лимит делегирования мандата. Банковского процессинга, реального списания, merchant attestation, SSO/MFA и сертификатов соответствия здесь нет. Каталог тестовый; интерпретатор понимает наушники/мышь и бюджет. Закрытие console прекращает demo polling; интегрированный агент должен пользоваться polling SDK или webhook и вызывать execute самостоятельно.
